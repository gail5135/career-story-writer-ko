# career-story-writer-ko

**단편적인 업무 메모를, 판단과 기여가 드러나는 한국어 커리어 이야기로.**

자기소개서·경력기술서·포트폴리오의 경험 설명을 돕는 Codex 스킬입니다. 문제의 배경부터 행동과 결과까지 연결하고, 핵심 정보가 부족하면 구체적으로 질문합니다. 지침은 영어로, 결과물은 한국어로 작성하도록 설계했습니다.

## 어떤 일을 하나요?

- 지원 문항과 직무에 맞춰 하나의 핵심 역량을 중심으로 경험을 정리합니다.
- 개인의 기여와 팀의 성과, 기대 효과와 확인된 결과를 구분합니다.
- 수치·기술·권한·성과를 지어내지 않습니다.
- 실패를 합리적인 선택으로 포장하지 않고 책임·대응·후속 변화를 설명합니다.
- 자소서는 문단, 경력기술서는 기여 중심 항목, 포트폴리오는 설명형으로 구성합니다. 요청한 형식이 우선입니다.

## 제작 배경

훈민정음 서두가 **문제의 원인 → 구체적인 문제 → 해결 행동 → 기대 효과**를 간결하게 설명한다는 관찰에서 시작했습니다.

| 서두에서 읽어낸 흐름 | 업무 경험에 적용할 질문 |
| --- | --- |
| 말과 문자가 맞지 않는 배경 | 어떤 조건에서 문제가 생겼는가? |
| 뜻을 충분히 표현하지 못하는 어려움 | 누가 어떤 어려움을 겪었는가? |
| 스물여덟 자의 창제 | 내가 직접 무엇을 했는가? |
| 쉽게 익혀 일상에서 쓰려는 목적 | 무엇이 달라졌거나, 무엇을 기대했는가? |

이는 해당 글을 논문 초록과 유사한 설명 구조로 읽은 제작자의 해석입니다. 실제 성과와 기대 효과는 구분하며, 제약·선택 이유·성찰은 필요할 때 덧붙입니다. 네 문단을 강제하는 템플릿은 아닙니다.

## 설치

Codex를 사용할 수 있는 환경이 필요합니다. 이 저장소에는 실행 스크립트나 별도 API 의존성이 없습니다.

### 방법 1. Codex에 설치 요청

Codex에서 다음과 같이 요청하세요.

```text
$skill-installer https://github.com/gail5135/career-story-writer-ko 의 루트에 있는 스킬을 설치해 줘.
```

### 방법 2. 직접 설치

Git이 설치된 macOS·Linux 터미널에서 실행합니다.

```bash
mkdir -p "$HOME/.agents/skills"
git clone https://github.com/gail5135/career-story-writer-ko.git "$HOME/.agents/skills/career-story-writer-ko"
```

Windows PowerShell에서는 다음을 실행합니다.

```powershell
New-Item -ItemType Directory -Force "$HOME/.agents/skills" | Out-Null
git clone https://github.com/gail5135/career-story-writer-ko.git "$HOME/.agents/skills/career-story-writer-ko"
```

같은 이름의 폴더가 이미 있으면 덮어쓰지 말고 기존 설치를 확인하세요. Git을 사용하지 않는 경우 GitHub의 **Code → Download ZIP**으로 다운로드하고, 압축을 풀어 `SKILL.md`가 `~/.agents/skills/career-story-writer-ko/SKILL.md`에 위치하도록 옮겨도 됩니다.

설치 후 `$career-story-writer-ko`를 입력해 호출합니다. 보이지 않으면 Codex를 재시작하세요. 이전 설치가 `~/.codex/skills` 등에 있다면 같은 스킬을 중복 설치하지 않도록 확인하세요. 설치 위치와 인식 방식은 [공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)를 참고하세요.

직접 Git으로 설치한 원본은 아래 명령으로 업데이트할 수 있습니다. 로컬에서 수정한 내용이 있으면 먼저 보관하세요.

```bash
git -C "$HOME/.agents/skills/career-story-writer-ko" pull --ff-only
```

## 사용 가이드

완성된 글이 없어도 됩니다. 기억나는 사실을 메모 형태로 적고, 모르는 항목은 모른다고 표시하세요. 아래 항목은 선택 사항이며 모두 채울 필요는 없습니다.

```text
$career-story-writer-ko

용도: 자기소개서 / 경력기술서 / 포트폴리오
지원 직무:
지원 문항:
분량과 형식:

당시 상황과 문제:
내 역할과 직접 한 일:
선택한 방법과 이유:
확인된 결과:
측정하지 않았거나 모르는 부분:
실패·한계·이후 바꾼 점:

위 메모를 바탕으로 정리해 줘. 핵심 정보가 부족하면 먼저 질문해 줘.
```

기본 출력은 **핵심 관점 한 문장 → 제목과 초안 → 필요한 경우 보완 정보**입니다. 용도를 지정하지 않으면 자기소개서 형식으로, 별도 분량이 없으면 자소서 초안을 약 600~900자로 작성하도록 합니다. 경력기술서와 포트폴리오에는 이 분량을 강제하지 않습니다.

정보가 부족하면 먼저 질문합니다. 사용자가 모른다고 답한 정보는 계속 요구하지 않고 확인된 사실로 범위를 좁힙니다. 기존 글을 붙여 넣고 구조나 강조점을 수정해 달라고 요청해도 됩니다.

## 사용 예시

아래 사례는 사용법을 설명하기 위한 **가상의 메모와 기대 동작**입니다. 실제 사용자의 경력이나 실행 결과를 인용한 것이 아닙니다.

### 1. 충분한 메모에서 경력기술서 작성

```text
$career-story-writer-ko
프론트엔드 경력기술서용으로 세 항목으로 정리해 줘.
- 네 화면에 입력 검증 로직이 따로 있어 동일한 규칙을 여러 곳에서 수정했음.
- 나는 공통 검증 함수를 제안하고 구현했으며, 두 화면에 적용했음.
- 나머지 두 화면은 동료가 적용했음.
- 공통 함수 테스트를 추가했고, 이후 규칙 변경은 공통 함수에서 처리했음.
- 작업 시간 절감률은 측정하지 않았음.
```

기대 동작: 제안·구현·두 화면 적용이라는 개인 기여와 동료의 적용 범위를 구분합니다. 측정하지 않은 시간 절감률을 만들지 않습니다.

### 2. 정보가 부족한 메모

```text
$career-story-writer-ko
자동화를 해서 업무 효율이 좋아진 경험을 자소서로 써 줘.
```

기대 동작: 무엇을 자동화했는지, 기존에 어떤 어려움이 있었는지, 본인이 직접 한 일과 확인된 변화가 무엇인지 질문합니다. 도구나 성과 수치를 추측하지 않습니다.

### 3. 실패 경험

```text
$career-story-writer-ko
실패를 통해 배운 점을 묻는 문항이야.
- 내가 맡은 배포에서 설정 확인을 누락해 기능이 일시적으로 동작하지 않았음.
- 문제 확인 후 팀과 함께 이전 버전으로 복구했음.
- 나는 이후 설정 확인 항목을 배포 체크리스트에 추가했음.
- 재발률은 아직 확인할 수 없음.
```

기대 동작: 확인 누락을 의도적인 트레이드오프로 포장하지 않습니다. 개인의 후속 조치와 팀의 복구를 구분하고, 재발 방지 효과가 검증됐다고 쓰지 않습니다.
