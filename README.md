# career-story-writer-ko

**단편적인 업무 메모를, 판단과 기여가 드러나는 한국어 커리어 이야기로.**

자기소개서·경력기술서·포트폴리오의 경험 설명을 돕는 Codex·Claude Code·Gemini CLI 공용 스킬입니다. 문제의 배경부터 행동과 결과까지 연결하고, 핵심 정보가 부족하면 구체적으로 질문합니다. 지침은 영어로, 결과물은 한국어로 작성하도록 설계했습니다.

## 어떤 일을 하나요?

- 지원 문항과 직무에 맞춰 하나의 핵심 역량을 중심으로 경험을 정리합니다.
- 개인의 기여와 팀의 성과, 기대 효과와 확인된 결과를 구분합니다.
- 수치·기술·권한·성과를 지어내지 않습니다.
- 실패를 합리적인 선택으로 포장하지 않고 책임·대응·후속 변화를 설명합니다.
- 자소서는 문단, 경력기술서는 기여 중심 항목, 포트폴리오는 설명형으로 구성합니다. 요청한 형식이 우선입니다.

## 제작 배경

훈민정음 서두가 **문제의 원인 → 구체적인 문제 → 해결 행동 → 기대 효과**를 간결하게 설명한다는 관찰에서 시작했습니다.

| 서두에서 읽어낸 흐름 | 업무 경험에 적용할 질문 |
| --- | --- |
| 말과 문자가 맞지 않는 배경 | 어떤 조건에서 문제가 생겼는가? |
| 뜻을 충분히 표현하지 못하는 어려움 | 누가 어떤 어려움을 겪었는가? |
| 스물여덟 자의 창제 | 내가 직접 무엇을 했는가? |
| 쉽게 익혀 일상에서 쓰려는 목적 | 무엇이 달라졌거나, 무엇을 기대했는가? |

이는 해당 글을 논문 초록과 유사한 설명 구조로 읽은 제작자의 해석입니다. 실제 성과와 기대 효과는 구분하며, 제약·선택 이유·성찰은 필요할 때 덧붙입니다. 네 문단을 강제하는 템플릿은 아닙니다.

## 설치

가장 간단한 방법은 이 페이지 주소와 아래 문구를 **Codex, Claude Code 또는 Gemini CLI**에 그대로 보내는 것입니다. 사용 중인 도구와 운영체제에 맞춰 설치하도록 요청할 수 있습니다.

```text
https://github.com/gail5135/career-story-writer-ko
이 저장소의 career-story-writer-ko 스킬을 내 개인 스킬로 설치해 줘. 이미 설치돼 있다면 중복 설치하지 말고 확인해 줘. 설치 후 호출 방법도 알려 줘.
```

### 직접 설치하기

세 도구 모두 이 저장소의 `SKILL.md`를 그대로 사용합니다.

| 도구 | 설치 | 호출 |
| --- | --- | --- |
| Codex | Codex에 `$skill-installer https://github.com/gail5135/career-story-writer-ko 의 루트 스킬을 설치해 줘` 요청 | `$career-story-writer-ko` |
| Claude Code | 아래 운영체제별 명령 | `/career-story-writer-ko` |
| Gemini CLI | `gemini skills install https://github.com/gail5135/career-story-writer-ko` | `career-story-writer-ko 스킬을 사용해 줘` |

Claude Code 설치에는 Git이 필요합니다. **macOS·Linux** 터미널에서는:

```bash
mkdir -p "$HOME/.claude/skills"
git clone https://github.com/gail5135/career-story-writer-ko.git "$HOME/.claude/skills/career-story-writer-ko"
```

**Windows**에서는 PowerShell을 열고 실행하세요:

```powershell
New-Item -ItemType Directory -Force "$HOME/.claude/skills" | Out-Null
git clone https://github.com/gail5135/career-story-writer-ko.git "$HOME/.claude/skills/career-story-writer-ko"
```

Codex의 채팅 설치 요청과 Gemini CLI의 `gemini skills install` 명령은 두 운영체제에서 동일합니다. 이미 설치된 폴더가 있다면 `git clone`을 다시 실행하지 마세요. 자세한 옵션은 [Claude Code](https://code.claude.com/docs/en/skills)·[Gemini CLI](https://geminicli.com/docs/cli/using-agent-skills/) 공식 문서를 참고하세요.

## 사용 가이드

아래 예시는 Codex 호출 표기를 사용합니다. Claude Code에서는 첫 줄을 `/career-story-writer-ko`로, Gemini CLI에서는 `career-story-writer-ko 스킬을 사용해 줘.`로 바꿔 사용하세요. 나머지 메모와 요청은 동일합니다.

완성된 글이 없어도 됩니다. 기억나는 사실을 메모 형태로 적고, 모르는 항목은 모른다고 표시하세요. 아래 항목은 선택 사항이며 모두 채울 필요는 없습니다.

```text
$career-story-writer-ko

용도: 자기소개서 / 경력기술서 / 포트폴리오
지원 직무:
지원 문항:
분량과 형식:

당시 상황과 문제:
내 역할과 직접 한 일:
선택한 방법과 이유:
확인된 결과:
측정하지 않았거나 모르는 부분:
실패·한계·이후 바꾼 점:

위 메모를 바탕으로 정리해 줘. 핵심 정보가 부족하면 먼저 질문해 줘.
```

기본 출력은 **핵심 관점 한 문장 → 제목과 초안 → 필요한 경우 보완 정보**입니다. 용도를 지정하지 않으면 자기소개서 형식으로 작성합니다. 별도 분량이 없으면 자기소개서·경력기술서·포트폴리오 초안 한 건당 공백 포함 약 500자(제목과 보완 정보 제외)를 목표로 합니다. 핵심 사실을 정확하게 담으려면 500자를 많이 넘겨야 할 경우, 필요한 이유를 설명하고 먼저 동의를 구합니다. 이미 긴 분량을 요청했다면 다시 묻지 않습니다.

정보가 부족하면 먼저 질문합니다. 사용자가 모른다고 답한 정보는 계속 요구하지 않고 확인된 사실로 범위를 좁힙니다. 기존 글을 붙여 넣고 구조나 강조점을 수정해 달라고 요청해도 됩니다.

## 사용 예시

아래 사례는 사용법을 설명하기 위한 **가상의 메모와 기대 동작**입니다. 실제 사용자의 경력이나 실행 결과를 인용한 것이 아닙니다.

### 1. 충분한 메모에서 경력기술서 작성

```text
$career-story-writer-ko
프론트엔드 경력기술서용으로 세 항목으로 정리해 줘.
- 네 화면에 입력 검증 로직이 따로 있어 동일한 규칙을 여러 곳에서 수정했음.
- 나는 공통 검증 함수를 제안하고 구현했으며, 두 화면에 적용했음.
- 나머지 두 화면은 동료가 적용했음.
- 공통 함수 테스트를 추가했고, 이후 규칙 변경은 공통 함수에서 처리했음.
- 작업 시간 절감률은 측정하지 않았음.
```

기대 동작: 제안·구현·두 화면 적용이라는 개인 기여와 동료의 적용 범위를 구분합니다. 측정하지 않은 시간 절감률을 만들지 않습니다.

### 2. 정보가 부족한 메모

```text
$career-story-writer-ko
자동화를 해서 업무 효율이 좋아진 경험을 자소서로 써 줘.
```

기대 동작: 무엇을 자동화했는지, 기존에 어떤 어려움이 있었는지, 본인이 직접 한 일과 확인된 변화가 무엇인지 질문합니다. 도구나 성과 수치를 추측하지 않습니다.

### 3. 실패 경험

```text
$career-story-writer-ko
실패를 통해 배운 점을 묻는 문항이야.
- 내가 맡은 배포에서 설정 확인을 누락해 기능이 일시적으로 동작하지 않았음.
- 문제 확인 후 팀과 함께 이전 버전으로 복구했음.
- 나는 이후 설정 확인 항목을 배포 체크리스트에 추가했음.
- 재발률은 아직 확인할 수 없음.
```

기대 동작: 확인 누락을 의도적인 트레이드오프로 포장하지 않습니다. 개인의 후속 조치와 팀의 복구를 구분하고, 재발 방지 효과가 검증됐다고 쓰지 않습니다.
